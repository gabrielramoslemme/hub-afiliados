## Descrição

Criar o projeto do painel de backoffice, que a Porto vai usar para analisar e aprovar os cadastros. A base reaproveita o layout, o tema e a estrutura de navegação já usados em outros painéis do time, descartando os recursos de domínio daqueles produtos.

Entra também a camada que conversa com a API: um ponto único por onde todas as chamadas passam, responsável por anexar a credencial do operador e por traduzir o erro que a API devolve em uma mensagem que a tela consegue exibir. Concentrar isso em um lugar evita que cada tela invente o seu próprio jeito de tratar falha.

## Critérios de aceite

- [ ] O painel sobe localmente com um comando e abre uma página inicial sem erros no navegador.
- [ ] O layout, as cores e a tipografia seguem o padrão dos painéis existentes do time.
- [ ] Todas as chamadas à API passam por um único ponto, que anexa a credencial do operador.
- [ ] Um erro devolvido pela API vira mensagem legível em português, sem quebrar a tela.
- [ ] O endereço da API é configurável por ambiente, sem alteração de código.

## Objetivo

Ter o painel rodando com layout, navegação e comunicação com a API já resolvidos, para que as telas de análise e aprovação sejam construídas direto sobre essa base.

## Job Story

Quando eu vou construir uma tela do painel, eu quero encontrar o layout, a navegação e a comunicação com a API já prontos, para me concentrar no que o operador precisa ver e decidir.
