## Descrição

Criar o repositório `porto-hub-afiliados`, que vai abrigar a API e o painel no mesmo lugar. Manter os dois juntos permite compartilhar configuração e, principalmente, os tipos de dados que o painel consome da API — quando um deles muda o formato de uma informação, o outro para de compilar na hora, em vez de a falha aparecer em produção.

O aplicativo do afiliado, feito em Flutter, fica em repositório próprio: não compartilha ferramental com os projetos em TypeScript e tem cadência de publicação própria, presa à aprovação das lojas. A ligação entre ele e a API é o contrato publicado no card 1.4.

Também entra aqui o ferramental comum: padrão de código, verificação de estilo, validação da mensagem de commit e os comandos únicos que rodam verificação e build de tudo.

## Critérios de aceite

- [ ] O repositório `porto-hub-afiliados` existe e está versionado.
- [ ] Um único comando instala as dependências de todos os projetos do repositório.
- [ ] Um único comando roda verificação de estilo, tipos, testes e build de todos os projetos.
- [ ] Padrão de código e regras de estilo são compartilhados, sem duplicação por projeto.
- [ ] Mensagens de commit fora do padrão acordado são recusadas automaticamente.
- [ ] O README explica em até cinco linhas o que é cada parte do repositório e como subir o ambiente.

## Objetivo

Ter um repositório único para API e painel, com ferramental compartilhado, para que mudanças que atravessam os dois sejam feitas e verificadas de uma vez só.

## Job Story

Quando eu preciso mudar uma informação que a API entrega e o painel exibe, eu quero fazer isso em um único repositório e ver a verificação apontar imediatamente o que quebrou, para não descobrir a inconsistência depois, já em produção.
